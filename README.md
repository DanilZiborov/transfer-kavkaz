# Transfer Kavkaz

Сайт индивидуальных пассажирских трансферов по Северному Кавказу.

Проект предназначен для привлечения клиентов из поисковых систем и удобной связи с перевозчиком. Базовый регион подачи — Кавказские Минеральные Воды; поездки в Архыз, Домбай, Приэльбрусье, Северную Осетию и другие направления согласовываются индивидуально. На сайте будут представлены популярные направления, автомобиль Hyundai Grand Starex (2010), фотографии, отзывы и способы связи: телефон, WhatsApp, MAX.

> **Статус: подготовка к разработке MVP.** Сейчас в репозитории согласованы требования и инструкции для Codex, но исходный код сайта ещё не создан.

## Технологии

Утверждённый стек MVP:

- **Astro 6** со статической генерацией (SSG).
- **TypeScript** в строгом режиме.
- **Нативный CSS** и CSS-переменные.
- **Нативный JavaScript / TypeScript** для интерактивных элементов.
- **Astro Content Collections + Zod** для данных направлений.
- **GitHub Actions + GitHub Pages** для сборки и размещения.

CMS, React, бэкенд, база данных, онлайн-бронирование и онлайн-оплата в MVP не предусмотрены.

## Страницы и функциональность

- **Главная** — шапка, широкий баннер с автомобилем и горной дорогой, «О нас», автомобиль, 4–6 популярных направлений, галерея, отзывы, контакты.
- **`/routes/`** — каталог направлений в виде простой сетки без поиска и фильтров.
- **`/routes/[slug]/`** — единый шаблон страницы направления; география подачи — города КМВ и другие места по договорённости.
- **Связь** — телефон, WhatsApp, MAX; CTA открывает выбор способа связи, на мобильных устройствах предусмотрена закреплённая нижняя панель.
- **Дизайн** — современный минимализм с тёплой атмосферой Кавказа, читаемым текстом, свободным пространством и умеренными анимациями.

Детали и критерии приёмки — в [ТЗ](docs/TZ.md).

## Локальная разработка

Исходный Astro-проект появится в следующем этапе. После его инициализации предполагаются стандартные команды:

```bash
npm install
npm run dev
npm run check
npm run build
npm run preview
```

**Пока эти команды не работают:** `package.json` и npm-скрипты ещё не созданы. При инициализации проекта Codex должен настроить их и обновить этот раздел при необходимости.

## MVP и коммерческий запуск

**MVP** — технически работающий прототип с демонстрационными фотографиями, текстами и отзывами. Демонстрационные материалы должны быть помечены и не должны вводить посетителей в заблуждение. Тестовые контакты не должны вести к посторонним людям.

**Коммерческий запуск** — отдельный этап: реальные фотографии, контакты, отзывы и тексты; согласование цен; собственный домен; открытие индексации; аналитика и продвижение.

Пока используется демонстрационный контент, сайт не предназначен для индексации. Механизм `noindex` не делает опубликованный сайт приватным.

## Качество и публикация

- Mobile-first, адаптивность от 320 CSS px.
- Доступность с клавиатуры и поддержка `prefers-reduced-motion`.
- Техническое SEO: статический HTML, метатеги, sitemap, robots, canonical.
- Цели мобильного Lighthouse: **Performance ≥ 90**, **Accessibility ≥ 90**, **SEO ≥ 95**; для проверки SEO учитывается режим отключённой индексации прототипа.
- Публикация планируется на **GitHub Pages** через GitHub Actions с корректным базовым путём для репозитория `transfer-kavkaz`.

**Важно:** возможность публикации Pages из приватного репозитория зависит от плана GitHub. Доступность деплоя нужно проверить до настройки GitHub Actions; опубликованный сайт может быть общедоступным даже при приватном исходном репозитории.

## Как работаем с Codex

1. Согласуем задачу на основе [ТЗ](docs/TZ.md).
2. Codex читает ТЗ и [AGENTS.md](AGENTS.md), изучает текущий код и вносит ограниченные по объёму изменения.
3. Для существенных изменений используем отдельную ветку и Pull Request.
4. Проверяем сборку, типы, адаптивность и поведение в браузере.
5. После проверки объединяем изменения и переходим к следующей итерации.

**Приоритеты:** простота поддержки, скорость загрузки, доступность, понятный интерфейс и соответствие утверждённому ТЗ.
