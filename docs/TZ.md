# Техническое задание
## Transfer Kavkaz — сайт индивидуальных пассажирских трансферов

**Версия документа:** 1.0, утверждена  
**Репозиторий:** `DanilZiborov/transfer-kavkaz`  
**Текущий этап:** подготовка к разработке MVP

---

## 1. Назначение проекта

Разработать современный, быстрый и адаптивный коммерческий сайт для индивидуальных пассажирских трансферов по Северному Кавказу.

Основная бизнес-цель — привлечение потенциальных клиентов из поисковых систем и предоставление удобного способа связаться с перевозчиком.

Сайт должен формировать доверие к услуге, демонстрировать автомобиль, показывать популярные направления и подчёркивать возможность индивидуального согласования поездок.

### 1.1. Бизнес-модель

- Один перевозчик, один автомобиль — Hyundai Grand Starex 2010 года.
- Индивидуальные трансферы без продажи отдельных пассажирских мест.
- Базирование перевозчика — Минеральные Воды.
- Подача автомобиля возможна из любого города КМВ: Минеральные Воды, Пятигорск, Кисловодск, Ессентуки, Железноводск.
- Другие места отправления и назначения согласовываются индивидуально.
- География перевозок — Северный Кавказ, включая Ставропольский край, КЧР, КБР, Северную Осетию и другие направления по договорённости.
- Поездки возможны в обоих направлениях.
- Стоимость согласовывается с перевозчиком.

Опубликованные маршруты не ограничивают географию предоставления услуги.

### 1.2. Язык

Только русский.

## 2. Границы MVP

MVP представляет собой полностью функциональный технический прототип сайта с согласованным дизайном, но с демонстрационным содержимым.

### В MVP обязательно

- Полная структура сайта.
- Адаптивная главная страница.
- Каталог направлений.
- Страницы отдельных направлений.
- Работающая навигация.
- Контактные элементы интерфейса.
- Фотогалерея с просмотром изображений.
- Раздел отзывов.
- Анимации и интерактивные элементы.
- Техническая SEO-подготовка.
- Автоматическая сборка и публикация на GitHub Pages.
- Проверка качества и производительности.

### Допускается в MVP

- Демонстрационные фотографии, включая сгенерированные изображения.
- Временные тексты.
- Демонстрационные маршруты.
- Примеры цен.
- Демонстрационные отзывы.
- Временное рабочее название и оформление без окончательного логотипа.

Временные отзывы и другие вымышленные сведения нельзя выдавать за настоящие. Демонстрационные контактные данные не должны направлять посетителей случайным третьим лицам.

### После MVP

- Согласование и публикация реальных материалов перевозчика.
- Настоящие контакты, фотографии, отзывы и цены.
- Окончательная редактура текстов.
- Покупка и подключение домена.
- Коммерческий запуск и открытие индексации.
- Подключение Яндекс Метрики.
- Подключение Яндекс Вебмастера и Google Search Console.
- Создание карточки перевозчика в Яндекс Бизнесе.

## 3. Структура сайта

Сайт многостраничный, но главная страница строится по принципу лендинга.

### 3.1. Главная страница `/`

Предусматривает следующие основные элементы:

1. Шапка с навигацией и контактами.
2. Главный баннер с фотографией горной дороги и автомобиля, заголовком и CTA.
3. Секция «О нас».
4. Секция «Автомобиль».
5. Блок популярных направлений.
6. Фотогалерея.
7. Отзывы клиентов.
8. Контакты.
9. Подвал сайта.

Содержание и точное расположение элементов внутри секций могут уточняться в ходе разработки и дизайн-итераций.

### 3.2. Каталог `/routes/`

- Адаптивная сетка карточек направлений.
- Без поиска, фильтров и группировки.
- Фотография, название и опциональная цена «от».
- Каждая карточка ведёт на страницу соответствующего направления.
- Порядок карточек определяется данными проекта.

### 3.3. Страницы направлений `/routes/[slug]/`

Один шаблон для всех направлений.

Содержание:

- Название направления.
- Основная фотография.
- Краткое описание услуги.
- Возможность отправления из всех городов КМВ.
- Возможность согласования других мест подачи.
- Опциональная стоимость «от».
- Кнопка «Узнать стоимость», открывающая выбор способа связи.

Время в пути и расстояние не отображаются.

Не создаются отдельные страницы для каждой комбинации города отправления и назначения.

### 3.4. Популярные направления на главной

- Показываем 4–6 направлений.
- Каждая карточка ведёт на соответствующую страницу.
- Ссылка «Все направления» ведёт в каталог.
- Состав и порядок популярных направлений задаются вручную.

## 4. Навигация и взаимодействие

### 4.1. Шапка

Закреплённая компактная шапка, доступная на всех страницах.

Пункты меню:

| Пункт | Действие |
|---|---|
| О нас | Переход к `/#about` |
| Автомобиль | Переход к `/#vehicle` |
| Маршруты | Открытие каталога `/routes/` |
| Контакты | Переход к `/#contacts` |

На десктопе контактные элементы располагаются справа.

На мобильных устройствах предусматривается компактное раскрывающееся меню.

Якорные переходы должны учитывать высоту закреплённой шапки.

### 4.2. Контактные действия

Три способа связи:

- Телефонный звонок.
- WhatsApp.
- MAX.

WhatsApp и MAX открывают личный чат с водителем без заранее подготовленного текста.

Телефонная ссылка использует `tel:`. На смартфоне открывается приложение звонков с подставленным номером.

Контактные данные должны храниться централизованно в конфигурации проекта.

### 4.3. Основные CTA

Кнопки «Узнать стоимость», «Заказать трансфер» и аналогичные открывают небольшое меню выбора:

- Позвонить.
- WhatsApp.
- MAX.

Меню закрывается нажатием снаружи, клавишей Escape или после выбора действия.

### 4.4. Нижняя мобильная панель

На смартфонах постоянно доступна закреплённая нижняя панель с тремя контактными действиями.

Панель:

- Не перекрывает контент.
- Учитывает безопасную область экрана.
- Работает на всех страницах.
- Не мешает прокрутке и навигации.

## 5. Фотогалерея

Обязательный функциональный раздел MVP на главной странице.

Требования:

- Адаптивное отображение фотографий.
- Увеличение изображения при нажатии (lightbox).
- Перелистывание фотографий.
- Поддержка свайпов на мобильных устройствах.
- Закрытие клавишей Escape.
- Возможность закрыть просмотр явной кнопкой.
- Оптимизированная загрузка изображений.
- Возможность менять набор фотографий через файлы проекта.

Отдельная страница галереи не требуется.

---

## 6. Отзывы

Обязательный функциональный раздел MVP на главной странице.

Используются собственные карточки, без сторонних виджетов.

Карточка может содержать:

- Имя автора.
- Текст отзыва.
- Оценку, если она доступна.
- Источник.
- Ссылку на оригинал, если она существует.

Данные отзывов хранятся непосредственно в проекте.

В MVP допустимы явно обозначенные демонстрационные отзывы. Перед коммерческим запуском их заменяют реальными.

## 7. Дизайн

### 7.1. Концепция

Современный минимализм с живой, тёплой туристической атмосферой Северного Кавказа.

Визуальные ориентиры:

- Чистый, современный интерфейс.
- Простая классическая вертикальная композиция.
- Большое количество свободного пространства.
- Крупная читаемая типографика.
- Фотографии гор, дорог, туристических направлений и автомобиля.
- Сдержанная цветовая палитра с природными акцентами.
- Отсутствие избыточных декоративных элементов и сложных многоколоночных композиций.

### 7.2. Верхняя часть главной

В первую очередь должны быть реализованы:

1. Компактная закреплённая шапка.
2. Широкий, но не полноэкранный баннер с горами, дорогой, автомобилем и CTA.
3. Просторная секция «О нас» с удобочитаемым текстом.

Баннер не должен занимать большую часть длинной главной страницы или искусственно растягиваться на всю высоту окна.

### 7.3. Анимации

Умеренные:

- Hover-эффекты.
- Плавные переходы меню.
- Плавная прокрутка.
- Деликатное появление секций.
- Ненавязчивые эффекты карточек и изображений.

Приоритет — CSS и лёгкий нативный JavaScript.

Обязательно учитывать `prefers-reduced-motion`.

Анимации не должны заметно ухудшать производительность или затруднять взаимодействие.

### 7.4. Процесс реализации дизайна

Имеющиеся изображения являются визуальными референсами, а не точными макетами.

Codex разрабатывает первую целостную версию сайта с учётом этих принципов.

Дальнейшее совершенствование дизайна происходит итерациями после просмотра работающего сайта в браузере.

## 8. Контент и данные

CMS, административная панель и база данных не предусмотрены.

Контент хранится в репозитории.

Для направлений используется единая типизированная модель данных с проверкой схемы через Zod.

Предусмотреть:

- Название направления.
- URL-идентификатор.
- Описание.
- Изображения.
- Опциональную стоимость «от».
- Признак отображения на главной.
- Порядок отображения.
- SEO-метаданные.

Все страницы направлений создаются по общему шаблону.

Добавление нового направления не должно требовать копирования компонентов или создания отдельной реализации страницы.

Контакты, галерея и отзывы также должны иметь централизованные источники данных.

## 9. SEO

### Основные требования

- Статически генерируемые HTML-страницы.
- Уникальные `title` и `meta description`.
- Семантическая HTML-разметка.
- Понятные URL.
- Корректные canonical URL.
- Генерация `sitemap.xml`.
- `robots.txt`.
- Метаданные Open Graph.
- Корректный атрибут `lang="ru"`.
- Правильная иерархия заголовков.

Ориентация на Google и Яндекс с особым вниманием к российскому поисковому трафику.

### SEO-стратегия

Основные посадочные страницы организованы по направлениям назначения, а не по отдельным парам городов.

Страница направления должна быть релевантна запросам о трансфере из разных городов КМВ.

Контент остаётся кратким, полезным и ориентированным на услугу.

### Особенность MVP

Тестовая публикация с демонстрационным содержимым не предназначена для поискового продвижения.

Предусмотреть режим, в котором тестовый сайт закрыт от индексации, с возможностью включить её при коммерческом запуске.

Техническое SEO и его проверка должны быть реализованы уже в MVP.

## 11. Нефункциональные требования

### 11.1. Адаптивность

- Mobile-first.
- Поддержка ширины от 320 CSS-пикселей.
- Смартфоны, планшеты, ноутбуки и большие экраны.
- Отсутствие горизонтальной прокрутки.
- Сохранение читаемости и удобства навигации.

### 11.2. Браузеры

Актуальные версии:

- Chrome.
- Firefox.
- Safari.
- Edge.

Internet Explorer отдельно не поддерживается.

### 11.3. Доступность

- Управление с клавиатуры.
- Видимый фокус интерактивных элементов.
- Контрастность текста и элементов управления.
- Корректные текстовые альтернативы изображений.
- Семантические элементы интерфейса.
- Доступное управление меню и фотогалереей.
- Поддержка уменьшения анимаций.

### 11.4. Производительность

Приоритет — минимальный вес страниц и быстрая загрузка на мобильных устройствах.

Целевые показатели Lighthouse:

| Метрика | Цель |
|---|---|
| Performance | ≥ 90 |
| Accessibility | ≥ 90 |
| SEO | ≥ 95 |

Проверяются главная, каталог и репрезентативные страницы направлений.

Измерения повторяются; результаты оцениваются с учётом колебаний среды тестирования.

Оптимизация изображений обязательна. Ресурсы ниже первого экрана загружаются по мере необходимости. Основное изображение первого экрана не должно откладываться без необходимости.

## 13. Критерии приёмки MVP

MVP готов, когда:

- [ ] Главная страница реализована.
- [ ] Работает шапка и навигация.
- [ ] Каталог направлений отображается и функционирует.
- [ ] Страницы направлений генерируются из данных.
- [ ] Популярные направления отображаются на главной.
- [ ] Работают контактное меню и мобильная контактная панель.
- [ ] Контактные ссылки корректно формируются при наличии настроенных данных.
- [ ] Фотогалерея открывается и позволяет перелистывать изображения.
- [ ] Раздел отзывов работает на демонстрационных данных.
- [ ] Реализованы согласованные анимации.
- [ ] Сайт адаптивен и доступен с клавиатуры.
- [ ] Техническое SEO реализовано.
- [ ] Достигнуты целевые показатели Lighthouse.
- [ ] Production-сборка проходит без ошибок.
- [ ] Сайт опубликован на GitHub Pages, прямые ссылки работают.
- [ ] Демонстрационные материалы не выдаются за реальные.

Наличие окончательного коммерческого контента не является условием приёмки MVP.
